> **읽는 법.** 2026-10-29 에 세운 계획서다. 목표는 엔진 분석 중 Compose 재구성 · 메인 스레드 연산 · 엔진
> I/O 할당을 줄이고, P0 ~ M7 개편과 Zenyth 리브랜딩이 남긴 잔재를 걷어 내는 것. 작업 브랜치는
> `refactor/perf-hygiene` — CI 가 녹색일 때만 `main` 으로 fast-forward 한다.

## 절대 규칙 — 어기면 그 커밋을 되돌린다

1. **화면 변화 0.** 레이아웃 · 여백 · 곡률 · 색 · 폰트 어느 1 px 도 달라지지 않는다. `-Pscreenshots=verify`
   (CI `screenshots.yml`, 골든은 CI 에서만 유효 — 로컬 폰트 래스터는 다르다)와 `ThemeContrastTest` 가 diff 0 으로 녹색.
2. **기능 회귀 0.** 엔진 프로세스 통신 · 온디바이스 수읽기 스트리밍 · 탭 좌표 · 기보 I/O · ViewModel 이
   화면에 내주는 계약을 지킨다.
3. **Phase 마다 승인.** 한 Phase 가 끝나면 측정과 CI 결과를 보고하고 다음 Phase 의 승인을 받는다.

## 진단 — 어디서 무게가 나오나

1. **병목은 Compose 앞단이다.** 엔진이 상태를 바꾸는 줄 하나마다 `SearchAggregator.snapshot()` 이 pvs · tags ·
   candidates · loseCells 넷을 통째로 복사하고, `BoardViewModel.uiState` 의 `combine` 이 `BoardUiState` 를 처음부터
   다시 짓는다. 그 안에 수와 무관한 일 — 오프닝 이름 4수 재분류, `openingGrade` 의 `PosKey`(대칭 8가지),
   `positionString`, `MoveGrader` 전 기보 재채점, `FontSpec.parse` 2회, `TagPalette` 생성 — 이 섞여 있다.
   `analyze()` 의 `channelFlow` 가 `viewModelScope` 에서 수집되므로 이 모두가 **메인 스레드**다.
2. **`BoardScreen` 이 맨 위에서 `ui` 전체를 읽는다.** `PositionCard` · `AnalysisCard` · `GameCard` · `MoveToolbar` ·
   `SummaryStrip` 등 17곳이 `ui: BoardUiState` 를 받으니 틱마다 화면 전체가 재구성되고,
   `ui.render.copy(provePulse = …)` 가 재구성마다 새 객체라 판도 매번 다시 그린다. 대국 시계(`GameRepositoryImpl`
   250 ms 틱)도 `game.state` 로 와서 대국 중 초당 4회 화면 전체가 재구성된다.
3. **Kotlin 2.4 는 strong skipping 이 기본이다.** 불안정 파라미터도 `===` 로 건너뛴다. 그러니 `@Immutable`
   일괄 부착보다 **상태를 쪼개 필요한 조각만 넘기는 것**이 핵심이다. 스크롤 오프셋을 컴포지션에서 읽는 곳은
   사실상 없고(`WhatsNew` 의 `canScrollForward` 하나, 이미 파생 상태), 람다 Modifier 로 바꿀 곳은
   `Segmented.kt` 의 `.offset(x = 애니메이션 값)` 하나다.
4. **판 그리기의 할당.** `drawValueText` · 돌 번호가 라벨마다 `android.graphics.Paint()` 를 새로 만들고
   `fontVariationSettings` 를 두 번 건다(typeface 파생 비용).
5. **안전망의 빈칸.** 골든 86장 중 Review · Rankings · Database · Explorer · Joseki · Prove · Tools · Connection
   화면은 0장, `AnalysisCard` 는 빈 상태만, `BoardViewModel` 테스트는 0개.

### Phase 2 — 엔진 I/O 할당 (UI 무관)

- `ResponseParser`: 줄마다의 `trim()` → `uppercase()`(줄 전체 복사)를 `startsWith(…, ignoreCase = true)` ·
  인덱스 처리로, `split(Regex("\\s+")).filter{}` 를 손 토크나이저로, `parseMoveList` 중간 리스트 제거.
- `SearchAggregator.snapshot()`: 바뀐 컬렉션만 복사(dirty 플래그), 나머지는 직전 불변 인스턴스 재사용.
  관찰값은 같고, 동일성이 유지되어 Phase 4 의 건너뛰기를 돕는다.
- 완전 무할당은 아니다 — Okio `readUtf8Line` 이 이미 String 을 만든다. 목표는 «줄당 String 1 + 응답 1».

검증: `ResponseParserTest` · `SearchAggregatorTest` · `*ProtocolTest` · 녹취 골든 동일 · 할당 측정 전후.

### Phase 3 — ViewModel 상태 파이프라인 (`BoardUiState` 형태 · 공개 API 유지)

- 수에만 매인 값(`openingNames` · `openingGrade` · `positionString`)을 `position` + **언어** 키 흐름으로 분리
  (`tr()` 결과라 언어를 빼면 언어 전환이 다음 수까지 안 보이는 회귀).
- 설정에만 매인 값(`TagPalette` · `FontSpec.parse` · 툴바 필터)을 `settings` 키로 분리.
- `records` 는 값이 같으면 갱신하지 않는다(지금은 스냅샷마다 전체 리스트 복사 → `winRateHistory` 새 리스트).
- 안정성 선언은 `core.model` 이 Compose 에 매이지 않게 컴파일러 `stabilityConfigurationFiles` 로.
- `analyze()` 를 Default 로 옮기는 것은 **여기서 하지 않는다** — `onSearchSettled` 가 `reading.value` 로
  즉답 수를 판정하므로 BestMove 와의 순서 역전 위험(Phase 6).

검증: `BoardViewModelTest` 전부 · 파이프라인 측정 전후 · 기존 시험 전부.

### Phase 4 — 재구성 범위 축소 (UI 코드, 픽셀 불변)

- `BoardScreen` 이 조각만 넘긴다(판 = `render`, 툴바 = 작은 상태, 시계 = `ClockRow` 만 `clock`). 기존
  `ui: BoardUiState` 시그니처는 얇은 어댑터로 남겨 **스크린샷 시험 파일을 바꾸지 않는다.**
- `provePulse` 는 그리기 단계에서만 읽는 람다로 → 초당 2회 전체 재구성이 판 다시 그리기로.
- `GameFileActions` · 콜백 람다 `remember`.
- `Segmented`: `.offset(x = …)` → `.offset { IntOffset(x.roundToPx(), 0) }`(`OffsetNode` 와 같은 반올림).
- `drawBoard`: 그리기 1회당 `BoardPaints` 하나로 굵기별 Paint 재사용(PNG 내보내기가 Default 스레드라
  공유 캐시는 쓰지 않는다), 번호 문자열 미리 생성, 화점 리스트 상수화.

검증: 골든 verify diff 0 · 재구성 횟수 기준선 대비 · 실기기(탭 좌표, 줌 120 % 가로 스크롤 탭, 롱프레스, 햅틱).
